The problem

Run five to ten agents at once and the bottleneck stops being the agents. It becomes you. Which one is blocked. Which one is burning quota. Which of nine identical terminal tabs that notification came from.

What it shows you

Nine signals, three that matter most

  • Context-window pressure, per session

    Each session reports how full its context window is, so you compact before hitting the limit — not after the agent starts forgetting.

    ctx 82% · compact suggested

  • Quota, burn rate, projected exhaustion

    Usage windows with the current burn rate and the clock time the quota runs out, for both the short and the weekly window.

    5h 25% · 79%/h · full in 57m

  • Died is not the same as finished

    An agent that crashed is distinguished from one that completed its run. No more guessing at silent terminal tabs.

    exit 1 · SIGTERM · 2m ago

How it works

Click a session, land in its exact terminal tab

Every session in the panel carries the handle of the terminal tab it is running in. That handle is read from the agent process's own environment — the variables the terminal exported when it spawned the shell — not from any terminal's session database. When you click a row, Agent Island uses the handle to focus that specific tab, in the terminal that owns it.

The mechanism differs per terminal, and so does the permission it needs:

Terminal focus mechanisms and required permissions
Terminal Handle How it is focused Permission
Warp WARP_FOCUS_URL open the warp://session/… URL none
iTerm2 ITERM_SESSION_ID AppleScript selects that session asked once
Terminal.app the controlling TTY AppleScript selects the matching tab asked once
kitty KITTY_WINDOW_ID kitty @ focus-window none
WezTerm WEZTERM_PANE wezterm cli activate-pane none

Why not read the terminal's database? Approaches that read a terminal's session store and replay keystrokes cannot distinguish tabs that share a working directory — so in a monorepo, where six tabs all sit in ~/work/repo, they land on the wrong one. The environment handle is unambiguous because the agent process itself carries it.

Install

Three lines in, two lines out

install 
$ git clone https://github.com/Tiwari1999/Agent-Island.git
$ cd Agent-Island
$ ./install.sh
uninstall 
$ python3 scripts/uninstall-hooks.py
$ rm -rf ~/Applications/AgentIsland.app

First launch: Agent Island is not notarized yet. On first open, right-click the app and choose Open, then confirm. Required once; subsequent launches are normal.

  • no screen recording
  • no full disk access
  • no accessibility permission for jumping
  • zero background processes when idle
  • fast session discovery
