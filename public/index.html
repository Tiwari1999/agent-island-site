The problem

Run five to ten agents at once and the bottleneck stops being the agents. It becomes you. Which one is blocked. Which one is burning quota. Which of nine identical terminal tabs that notification came from.

How it works

Click a session, land in its exact terminal tab

Every session in the panel carries the handle of the terminal tab it is running in. That handle is read from the agent process's own environment: the variables the terminal exported when it spawned the shell. It is not read from any terminal's session database. When you click a row, Agent Island uses the handle to focus that specific tab, in the terminal that owns it.

The mechanism differs per terminal, and so does the permission it needs:

Terminal focus mechanisms and required permissions
Terminal Handle How it is focused Permission
Warp WARP_FOCUS_URL open the warp://session/… URL none
iTerm2 ITERM_SESSION_ID AppleScript selects that session asked once
Terminal.app the controlling TTY AppleScript selects the matching tab asked once
kitty KITTY_WINDOW_ID kitty @ focus-window none
WezTerm WEZTERM_PANE wezterm cli activate-pane none

Why not read the terminal's database? Approaches that read a terminal's session store and replay keystrokes cannot distinguish tabs that share a working directory, so in a monorepo, where six tabs all sit in ~/work/repo, they land on the wrong one. The environment handle is unambiguous because the agent process itself carries it.

No Gatekeeper warning: Homebrew builds it on your Mac, so nothing is quarantined and it opens normally. Before you install

macOS says it cannot check the app for malicious software

It will. The build is not notarised yet, so Gatekeeper shows a dialog whose only buttons are Move to Trash and Cancel. The app is not quarantined for anything it does; it has simply not been through Apple's notary service.

To open it the first time: right-click (or Control-click) AgentIsland.app in Finder, choose Open, then click Open in the dialog that follows. That dialog does have an Open button. macOS remembers the choice, so this is once per install.

If you prefer the terminal:

xattr -d com.apple.quarantine /Applications/AgentIsland.app
What permissions does it ask for, and why

Automation, and only when you first click a row to jump. Focusing another app's window is an AppleEvent, so macOS asks once per terminal. Decline it and everything else still works; you lose the jump.

There is no accessibility permission, no screen recording, and no network access. Session data is read from files the agents already write on your own disk.

Which terminals does it work with

Jumping to the exact tab works in tmux, Warp, iTerm2, Terminal.app, kitty and WezTerm. Typing a reply back into the session works in tmux, iTerm2, kitty and WezTerm.

Terminal.app and Warp are read-only for replies on purpose: the only API either publishes runs its argument as a command rather than typing it, which is not a thing to point at someone's shell.

Does it slow the machine down

A refresh spawns zero subprocesses, and the test suite enforces that. Sessions are found by reading files, not by shelling out. When every agent is idle the panel animates nothing.

Which agents does it track

Claude Code, Codex and Cursor. Each is found through the files that agent already writes, so there is nothing to configure per project. Agents on machines you SSH into show up in the same list as local ones.

How do I remove it

Run python3 scripts/uninstall-hooks.py from the checkout, then move the app to the Trash. The script removes the hooks it added and leaves any other tool's hooks alone.

Stop counting terminal tabs.

Run as many agents as your quota allows. The notch keeps count for you.
