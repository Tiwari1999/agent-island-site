Act

Answer without switching tabs

Permission cards and questions are answered in the notch. Nothing is sent until you press submit.

Approve from the notch

Permission cards answered with ⌘⌥A / ⌘⌥D, without leaving what you were doing.

Answer questions

AskUserQuestion prompts answered in place — options on ⌘⌥1–⌘⌥4, plus a free-text field for your own words.

Plan review

Read the full Markdown plan and approve it from the notch, with a 55-second window instead of 20.

Sliding window

A visible countdown before an unanswered question hands back to the terminal. Every interaction pushes it forward, so answering never times out under you.

Or answer in the chat

One click releases the turn so Claude's own picker appears in the terminal, and the notch keeps a read-only copy.

Alerts that respect you

Desktop notifications only when you are not already looking at it.

The jump

Land on the exact tab

Click a row and arrive at that agent's own tab. The session handle comes from the agent process's own environment, so there is no database to read and no keystroke loop to fight — and it resolves correctly even when every tab shares one repo.

Other notch apps resolve Warp tabs by reading warp.sqlite and driving a keystroke loop. That cannot tell apart tabs sharing a working directory — so in a monorepo it lands on the wrong one.
Install

Two commands, no account

Everything runs locally. No server, no telemetry, no API key, no subscription — it reads only what your agents already write to your own disk.

From source

git clone https://github.com/Tiwari1999/Agent-Island.git
cd Agent-Island
./install.sh

# builds a release binary, assembles the app,
# registers the hooks, and launches it

Removing it

python3 scripts/uninstall-hooks.py
rm -rf ~/Applications/AgentIsland.app

# removes only its own hook entries and
# restores a statusLine it wrapped
From a release DMG: right-click the app and choose Open, then Open again. These builds are not notarized yet, so a double-click gives “cannot be opened because the developer cannot be verified”. That is macOS's own way of saying you trust it, and only the first launch needs it. There is no xattr command to run — be suspicious of any project that gives you one.
